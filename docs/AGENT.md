# Agent 接入

Agent 是默认关闭的编译内置模块。目前只列出已实现的 Codex 接入。它连接已有 Desktop 或 CLI daemon 的原会话，不启动新 daemon／App Server、不创建或派生会话，不改变 Desktop 启动方式。

## 启用与 Hooks 管理

模块开关与 Codex 接入开关共同决定是否执行 I/O。Codex 接入偏好默认开启，但不绕过模块总开关。启用后优先发现已有原生连接；Hooks 后备独立保存、默认关闭，只有明确启用后才允许按需安装和使用。

Hooks 管理入口在模块关闭时仍可用。打开管理页只读；手动安装会准备停用的辅助程序，不自动开启后备。移除 Hooks 同时清除后备偏好，避免重新启用模块后自动安装。关闭提供方停止全部来源，关闭后备只停止其监听器和记录观察者，保留原生订阅。

自动维护只更新已识别的 NotchX 定义和辅助程序，保留备份及其他工具的配置。新建或变更定义仍需用户在 Codex 中信任；NotchX 不写信任哈希、不开启全局禁用功能、不改变审批或自动审查策略，拒绝不安全链接和异常配置。辅助程序停用后返回中性结果；配置写入、daemon 确认和 Desktop 运行时刷新分别显示，不能互相替代。运行时刷新前仍可能启动已注册命令，不保证零进程开销。

“检查连接”只刷新现有订阅、目录与维护状态，不发送消息或隐式开启 Hooks。连接状态、诊断、安装状态和信任状态不是同一件事。

## 展示与消息

岛内展示活动、用户消息简短预览、计划、子代理摘要、待回答问题和受支持审批。不展示推理、完整最终答复、工具输出或差异；建议类事件不作为任务或可发送动作。

每个会话的输入框使用该原会话的当前能力：运行中默认“引导”，以“排队”为次要操作，结束后使用“发送”。等待问题或审批时不接受普通消息写入。问题只提醒并打开 Codex 回答，不在岛内提交答案。

- Desktop 写入重新确认原所有者、模型设置和新鲜的精确会话／轮次快照。引导使用 Desktop 的最新活动语义，不提供 daemon 的严格预期轮次前置条件。
- Desktop 排队使用兼容的本地队列整表设置路径，不是原生 queue/add 或原子多写者追加。确认要求精确所有者 ACK 与匹配的推送或已提交文件回读；NotchX 只串行化自身写入，不能排除 Desktop 同时修改整表的竞争。
- daemon 使用原线程的 turn/start、严格 turn/steer 和探测确认后的 thread/queue/add，响应与请求关联。
- 操作只提交一次，不跨通道或所有者自动补发。结果不确定时保留文本并阻止直接重试，须用户检查原会话后明确确认。

草稿按会话保存在内存，切换或收起不丢失；仅确认成功且未被继续编辑的文本会清空。关闭接入取消待处理操作并保留未确认草稿，退出应用不持久化草稿。普通预览不抢焦点，主动编辑才持有岛内交互。

## 原生通道与数据边界

Desktop IPC 是版本敏感的私有兼容协议，不是公开 App Server 控制套接字。能力取决于初始化、协议版本、所有者和已识别状态结构；未知形状、修订缺口或断线撤回覆盖并有界恢复，不猜测写入能力。

Desktop 状态与审批预检帧上限为 32 MiB；保留状态另有单订阅约 4 MiB／120,000 节点和总计约 16 MiB 的边界。只保留最近两轮所需公共内容，旧轮次保留索引和顺序而非正文。新成为当前轮次的旧内容不足时，重新取快照，不投影缺失数据。

daemon 通过验证过的同用户本地套接字连接已有服务，确认已加载线程后订阅。thread/resume 只携带原 threadId 和 excludeTurns；加载状态发生竞争时可能重新加载同一 UUID，但不创建新会话。请求句柄绑定原连接，断线、停用和未知事件撤回能力，迟到结果不得复活状态。

目录只读已知本地 SQLite 模式，最多读取 40 条近期用户会话元数据，不扫描替代数据库。目录记录不能证明正在运行、Desktop 来源或完整活动清单。子代理需真实身份与父子关系；父级记录提供的摘要不虚构子轮次和控制能力，不重复增加根任务计数。

## Hook 后备与审批

随应用打包的 NotchXAgentBridge 读取标准输入，通过同用户 Unix 套接字发送有界信封；不启动 NotchX、不注入上下文。套接字和父目录受权限、UID 和单所有者锁保护，客户端数量、帧大小及等待期限均受限。

辅助程序只可读取事件明确指定且位于所选会话目录内的记录路径，对元数据与尾部做有界读取，不枚举历史。应用最多观察八个已验证活跃文件，从文件末尾读取新追加的公共进度、问题和生命周期记录；不恢复旧对话内容。停用、轮次替换和结束关闭观察者并拒绝迟到结果。

Hook 审批只支持明确人工审查者、完整有界命令和有效请求通道。原生通道还支持已识别的命令／文件变更审批；身份、轮次、所有者、审阅内容与允许决策必须一致。网络／额外权限、未知形式、全会话文件授权等留在 Codex。拒绝与取消轮次不同；提交决定或本地 ACK 不代表命令已执行，不确定提交不自动重试。

打开会话使用经过验证的技术 ID 和注册处理器 com.openai.codex，经宿主外部导航入口执行。URL 合法不等于真实界面已跳转成功。Stop 表示轮次结束，不表示项目完成；来源未知、内部运行和建议事件不能产生虚假关注。

## 验证

原生测试覆盖身份、旧事件拒绝、真实隔离套接字、请求确认、队列推送、配置保护、取消和界面布局。测试不安装用户 Hooks，也不能证明当前 Desktop 版本、真实审批或物理灵动岛已验收。当前必需检查见 [验收清单](ACCEPTANCE.md)，参考项目与许可见 [第三方说明](../THIRD_PARTY_NOTICES.md)。
